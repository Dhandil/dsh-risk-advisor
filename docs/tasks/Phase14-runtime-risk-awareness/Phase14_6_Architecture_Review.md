## Review decisions

**A1 — No product changes.** Exactly scoped new integration tests, their optional test fixture and one new package test script are acceptable. If real product defects appear, stop and seek independent architecture repair scope rather than edit `src/**`, accepted tests or Harness.

**A2 — Actual Host/Browser seams.** Tests exercise real package Host `apply()`, pinned Harness Session/approval/Tool/connection, browser-rendered original Dock and both optional notes. Fake RPC/qualified-evidence injections are permitted for deterministic edge cases only and must be distinguished from integrated runtime proofs. No demand that mutually exclusive ordinary-risk and native approval display simultaneously.

**A3 — Independent retirement and authority.** A suppressed/missing F1/F2 Finding must never be resurrected by a 14.4 history or 14.5 note. Losing a 14.5 current verifier cannot delete the underlying Phase12 F2. Losing Guidance cannot manufacture or suppress the verified current error. A history note is not a cause or a permission. Active native approval owns final action.

**A4 — Lifetime/scale.** One Host route per endpoint per generation, no stale listeners; bounded Session stores and Host snapshots; Client 1.5s Host timestamp freshness and 1Hz reads; no new data persistence, new telemetry or secrets in wire or logs. All new tests join the existing ordered Full.

**A5 — Closure is a gated evidence status, not a launch claim.** A complete fresh Full, offline Browser production module smoke, static/privacy and accepted-performance bounds, exact repo/Harness SHAs, and a written open-validation register precede independent review. Success authorizes a docs-only Phase14 Completion Report and guarded main advancement; Phase13.3 remains open.
